# Экран аккаунта: методичка по реализации

Этот файл можно перенести на другой компьютер отдельно от чата. Пути ниже указаны относительно корня проекта FitApp. Объяснение соответствует текущей реализации, включая переключение русского и английского языков.

Цель методички — понять, что находится в каждом файле, проследить загрузку и сохранение профиля и подготовить понятный ответ преподавателю.

## 1. Главная идея

Экран аккаунта разделён на четыре блока:

1. **Шапка профиля** — аватар-заглушка, имя, рост, вес и желаемый вес.
2. **Личные данные** — поля ввода и кнопка «Сохранить».
3. **Приложение** — тема, единицы измерения и язык.
4. **Аккаунт** — визуальные заглушки действий с учётной записью.

Данные проходят такой путь:

```text
Поля формы
    ↓ пользователь нажал «Сохранить»
ProfileController
    ↓
ProfileDao
    ↓
SQLite
```

После успешной записи:

```text
ProfileController обновляет сохранённую модель
    ↓
notifyListeners()
    ↓
SettingsScreen перестраивается
    ↓
ProfileHeader получает новые значения
```

**Главное различие: текст в форме — это черновик, а данные в контроллере — сохранённый профиль.**

Например, в базе записан вес 78 кг. Пользователь ввёл в поле 77 кг, но ещё не нажал «Сохранить». В верхней карточке остаётся 78 кг. После успешного сохранения там появится 77 кг.

## 3. С чего начинается работа: `main.dart`

В `MultiProvider` зарегистрирован контроллер профиля:

```dart
ChangeNotifierProvider(
  create: (_) => ProfileController(ProfileDao())..load(),
),
```

Здесь выполняются три действия:

1. Создаётся `ProfileDao` — объект для запросов к базе.
2. Он передаётся в конструктор `ProfileController`.
3. У созданного контроллера вызывается `load()`.

Запись с `..load()` использует каскадный оператор. Она означает: вызвать метод у созданного объекта и продолжить использовать сам объект.

По смыслу это можно развернуть так:

```dart
final controller = ProfileController(ProfileDao());
controller.load();
return controller;
```

По умолчанию Provider создаёт объект при первом обращении к нему. Поэтому сама регистрация в списке ещё не означает, что запрос к базе уже завершился.

Контроллеры подключены выше экранов, чтобы разные виджеты могли получать один общий экземпляр.

## 4. Загрузка профиля: `profile_controller.dart`

Контроллер содержит:

```dart
UserProfile _profile = const UserProfile();
UserProfile get profile => _profile;

bool _isLoading = true;
bool get isLoading => _isLoading;

bool _hasLoadError = false;
bool get hasLoadError => _hasLoadError;
```

- `_profile` — текущий сохранённый профиль.
- `_isLoading` — идёт ли загрузка.
- `_hasLoadError` — произошла ли ошибка загрузки.
- Геттеры дают интерфейсу возможность читать эти значения.

Метод `load()`:

```dart
Future<void> load() async {
  _isLoading = true;
  _hasLoadError = false;
  notifyListeners();
  try {
    _profile = await _dao.getProfile();
  } catch (_) {
    _hasLoadError = true;
  } finally {
    _isLoading = false;
    notifyListeners();
  }
}
```

Логика по шагам:

1. Устанавливаем признак загрузки и сбрасываем предыдущую ошибку.
2. Уведомляем интерфейс: нужно показать индикатор.
3. Запрашиваем профиль у DAO и ждём результат через `await`.
4. Если произошла ошибка, запоминаем это в `_hasLoadError`.
5. Блок `finally` выполняется и при успехе, и при ошибке: загрузка заканчивается, интерфейс получает уведомление.

`Future<void>` означает, что операция асинхронная, а отдельного значения результата она не возвращает. Её завершения можно дождаться.

`notifyListeners()` доступен потому, что контроллер наследуется от `ChangeNotifier`. Метод уведомляет подписанные виджеты об изменениях.

## 5. Что делает DAO: `profile_dao.dart`

DAO — отдельный класс для операций с базой данных. Здесь находятся запросы, а не оформление экрана.

Чтение:

```dart
Future<UserProfile> getProfile() async {
  final db = await _db.database;
  final rows = await db.query('profile', where: 'id = ?', whereArgs: [1]);
  if (rows.isEmpty) {
    return const UserProfile();
  }
  return UserProfile.fromMap(rows.first);
}
```

По шагам:

1. Получаем открытое подключение к базе.
2. Ищем в таблице `profile` запись с `id = 1`.
3. Если записи ещё нет, возвращаем пустую модель.
4. Если запись есть, преобразуем первую строку результата в `UserProfile`.

`?` в условии — место для параметра. Его значение передаётся отдельно в `whereArgs`.

### Почему именно `id = 1`

Пока авторизации нет, приложение хранит **один локальный профиль**.

Число 1 — технический идентификатор этой единственной записи. Это не идентификатор пользователя Firebase.

Сохранение:

```dart
await db.insert(
  'profile',
  profile.toMap(),
  conflictAlgorithm: ConflictAlgorithm.replace,
);
```

Модель всегда передаёт `id = 1`. При первой записи профиль создаётся, а при следующих сохранениях запись с тем же ID заменяется.

Это соответствует текущей задаче с одним профилем. Для нескольких аккаунтов понадобится другая привязка данных.

## 6. Модель профиля: `user_profile.dart`

`UserProfile` описывает, какие данные есть у профиля:

```dart
final String firstName;
final String lastName;
final String middleName;
final String birthDate;
final String email;
final String phone;
final double? height;
final double? weight;
final double? targetWeight;
```

Текстовые поля по умолчанию содержат пустые строки. Рост, вес и цель могут быть `null`, если пользователь их не указал.

`final` запрещает изменить поле после создания объекта. Поэтому при сохранении формы создаётся новый объект `UserProfile` со всеми актуальными значениями.

### `toMap()`

Преобразует объект в карту для записи в SQLite:

```dart
'first_name': firstName,
'weight': weight,
```

Слева указано имя столбца таблицы, справа — значение поля объекта.

### `UserProfile.fromMap()`

Выполняет обратное преобразование: из строки результата запроса создаёт объект профиля.

Например:

```dart
firstName: map['first_name'] as String,
```

Выражение:

```dart
(map['weight'] as num?)?.toDouble()
```

означает: взять число, которое также может быть `null`, и, если число есть, преобразовать его в `double`.

### `displayName`

Геттер объединяет имя и фамилию:

```dart
final name = '$firstName $lastName'.trim();
return name;
```

Он не обращается к базе. Если имя и фамилия пустые, возвращается пустая строка. Надпись «Имя не указано» выбирает уже интерфейс с учётом языка.

## 7. Сборка страницы: `settings_screen.dart`

Экран получает контроллер:

```dart
final controller = context.watch<ProfileController>();
```

`watch` означает, что виджет подписывается на изменения контроллера. После `notifyListeners()` Flutter вызывает его `build()` заново.

Экран выбирает одно из трёх состояний:

1. Идёт загрузка — показать индикатор.
2. Загрузка закончилась ошибкой — показать сообщение и кнопку «Повторить».
3. Профиль загружен — показать четыре блока.

Основная сборка:

```dart
ProfileHeader(profile: controller.profile),
ProfileForm(initialProfile: controller.profile),
const AppSettingsSection(),
const AccountSection(),
```

Шапке передаётся профиль для отображения. Форме передаётся профиль для начального заполнения полей.

Блоки находятся в `Column`, обёрнутом в `SingleChildScrollView`. Скролл позволяет прокручивать страницу. Все четыре блока остаются в дереве, поэтому при обычной прокрутке форма не удаляется вместе с введённым текстом.

## 8. Шапка: `profile_header.dart`

`ProfileHeader` — это `StatelessWidget`. Он получает модель через параметр:

```dart
final UserProfile profile;
```

И отображает:

- имя и фамилию;
- рост;
- текущий вес;
- желаемый вес;
- аватар-заглушку.

Внутри файла есть приватные виджеты `_AvatarPlaceholder` и `_MetricCard`. Они нужны только для оформления этой шапки.

Если измерение не заполнено, карточка показывает тире. Если число целое, например `78.0`, оно отображается как `78`; дробное значение сохраняется, например `78.5`.

Шапка не читает контроллеры текстовых полей и не выполняет SQL-запросы. Она показывает ту модель, которую получил экран.

**Почему StatelessWidget обновляется?** У него нет собственного изменяемого состояния, но он может перестраиваться и получать новые параметры. После сохранения экран передаст в шапку обновлённый профиль.

## 9. Форма: `profile_form.dart`

Это `StatefulWidget`, поскольку форме нужно хранить введённый текст и состояние кнопки сохранения.

### Контроллеры полей

У каждого поля свой контроллер:

```dart
final _firstNameController = TextEditingController();
final _weightController = TextEditingController();
```

`TextEditingController` связан с полем ввода. Через его свойство `.text` можно прочитать введённый текст или задать начальный.

Не путай два вида контроллеров:

| Контроллер | Что хранит и делает |
|---|---|
| `TextEditingController` | Текст конкретного поля ввода. |
| `ProfileController` | Сохранённый профиль, загрузку и взаимодействие с DAO. |

### `initState()`

Вызывается один раз при создании объекта состояния формы:

```dart
_firstNameController.text = profile.firstName;
_weightController.text = _formatNumber(profile.weight);
```

Так в поля попадают сохранённые значения.

Это не сделано в `build()`, потому что `build()` вызывается многократно. Повторное заполнение полей при каждом построении могло бы затирать ввод пользователя.

### `dispose()`

Вызывается, когда объект состояния формы окончательно удаляется. В нём освобождаются контроллеры:

```dart
_firstNameController.dispose();
_weightController.dispose();
```

### `_buildField()`

Создаёт одинаково оформленную строку: подпись слева и поле справа.

Пример вызова:

```dart
_buildField(
  l10n.firstName,
  _firstNameController,
  placeholder: l10n.notSpecified,
)
```

Метод получает подпись, контроллер, подсказку и при необходимости тип клавиатуры. Он не выполняет сохранение.

Числовая клавиатура удобнее для ввода веса, но сама по себе не заменяет проверку значения.

### `_saving` и `_saved`

- `_saving` показывает, что запись в базу ещё выполняется. На это время кнопка сохранения отключается, а поля становятся доступны только для чтения.
- `_saved` показывает, что последнее сохранение было успешным. На кнопке появляется «Сохранено».
- При следующем редактировании поля `_saved` сбрасывается, и кнопка снова показывает «Сохранить».

`setState()` сообщает Flutter, что локальное состояние формы изменилось и её интерфейс нужно перестроить.

## 10. Полный цикл сохранения

Ищи метод `_save()` в `profile_form.dart`.

### Шаг 1. Проверка повторного нажатия

```dart
if (_saving) return;
```

Если сохранение уже идёт, второй запрос не запускается.

### Шаг 2. Чтение полей

```dart
final firstName = _firstNameController.text.trim();
```

`trim()` убирает пробелы по краям.

Для чисел дополнительно заменяется запятая на точку:

```dart
final weight = _weightController.text.trim().replaceAll(',', '.');
```

Поэтому можно ввести как `78.5`, так и `78,5`.

### Шаг 3. Проверки

- Рост, вес и цель: если заполнены, должны быть конечными числами больше нуля.
- Дата рождения: если заполнена, должна быть существующей датой в формате ДД.ММ.ГГГГ, не раньше 1900 года и не в будущем.
- Email: если заполнен, проходит простую проверку структуры, например наличия одного `@` и точки в домене.
- Телефон сейчас сохраняется как текст без отдельной проверки номера.

Все поля сейчас можно оставить пустыми. Проверка email не подтверждает существование адреса и не создаёт аккаунт.

Дата разбивается через `split('.')`, части преобразуются через `int.tryParse()`. После создания `DateTime` проверяются день, месяц и год: это позволяет отсеять, например, 31 февраля.

При неправильном вводе `_showError()` открывает `CupertinoAlertDialog`, после чего `_save()` заканчивается через `return`. Запрос в базу не выполняется.

### Шаг 4. Создание модели

```dart
final profile = UserProfile(
  firstName: firstName,
  lastName: lastName,
  // Остальные поля находятся в исходном методе.
  weight: double.tryParse(weight),
);
```

Это сокращённый пример. В реальном методе передаются все поля.

`double.tryParse()` превращает строку в число. Для пустой строки получается `null`, что соответствует незаполненному измерению.

### Шаг 5. Сохранение через контроллер

```dart
await controller.save(profile);
```

`await` позволяет дождаться записи, прежде чем показать успешный результат.

В `ProfileController`:

```dart
Future<void> save(UserProfile profile) async {
  await _dao.save(profile);
  _profile = profile;
  notifyListeners();
}
```

Порядок важен: сначала DAO записывает данные, затем контроллер обновляет свою модель. При ошибке записи сохранённое состояние контроллера не заменяется новым.

В текущей реализации контроллер после записи не перечитывает профиль из базы: он сохраняет в `_profile` тот объект, который только что успешно передал DAO.

### Шаг 6. Обновление страницы

`notifyListeners()` уведомляет `SettingsScreen`, потому что там используется `watch`.

Экран перестраивается и передаёт новый профиль в `ProfileHeader`. В карточках появляются сохранённые измерения.

Состояние существующей формы при обычном перестроении сохраняется: она остаётся виджетом того же типа на том же месте дерева. `initState()` повторно из-за одного `notifyListeners()` не вызывается.

### Шаг 7. Результат операции

При успехе форма устанавливает `_saved = true`.

При ошибке открывается сообщение, а введённый текст остаётся в контроллерах полей, чтобы можно было повторить сохранение.

В `finally` сбрасывается `_saving`.

Проверка `mounted` перед обновлением состояния означает: форма ещё находится в дереве. Пока выполнялся `await`, пользователь мог уйти со страницы.

## 11. База данных: `database.dart`

База хранится в файле `workouts.db`. Это общая база приложения, в ней есть таблица тренировок и таблица профиля.

### Singleton

```dart
AppDatabase._internal();
static final AppDatabase instance = AppDatabase._internal();
```

Приватный конструктор не позволяет создавать экземпляры из других библиотек. Общее поле `instance` предоставляет экземпляр управления базой.

DAO получает его так:

```dart
final AppDatabase _db = AppDatabase.instance;
```

Здесь DAO не создаёт новую базу, а получает ссылку на общий объект.

### Открытие подключения

```dart
Future<Database>? _db;
Future<Database> get database => _db ??= _open();
```

`??=` присваивает значение только тогда, когда слева `null`.

Здесь сохраняется `Future` открытия подключения. Если два DAO одновременно впервые запросят базу, они будут ожидать один и тот же результат открытия.

### Версия базы

Сейчас `_currentVersion = 2`.

- Для новой базы `onCreate` создаёт обе таблицы.
- Для базы версии 1 `onUpgrade` добавляет таблицу профиля.
- Существующая таблица тренировок при этом не удаляется.

Изменение схемы через увеличение версии называется миграцией. Новая версия файла Dart сама по себе не создаёт столбцы в уже существующей базе — для этого и нужен `onUpgrade`.

## 12. Настройки: отдельный контроллер

Файлы:

- `widgets/settings/app_settings_section.dart` — переключатели и подписи.
- `controllers/app_settings_controller.dart` — выбранные значения.
- `main.dart` — применение значений к приложению.

### Смена темы

```text
CupertinoSwitch
→ AppSettingsController.setDarkMode(value)
→ изменение _isDarkMode
→ notifyListeners()
→ Consumer в main.dart
→ выбор AppTheme.dark или AppTheme.light
```

Цвета находятся в `theme/app_theme.dart`. Динамические цвета выбирают свой вариант в зависимости от яркости темы.

### Смена языка

```text
Сегмент RU / EN
→ AppSettingsController.setLanguage(value)
→ изменение _language
→ notifyListeners()
→ locale: Locale(controller.language) в CupertinoApp
→ обновление переводимых надписей
```

Надпись получается так:

```dart
final l10n = AppLocalizations.of(context);
Text(l10n.save)
```

Значения хранятся в `app_ru.arb` и `app_en.arb`. Класс `AppLocalizations` создаёт генератор Flutter.

При смене языка введённое пользователем имя не переводится: это данные, а не надпись интерфейса.

### Единицы измерения

Строка показывает `кг / см` или `kg / cm`. Это перевод подписи. Переключения на фунты и футы и пересчёта значений сейчас нет.

### Что сохраняется после закрытия

| Данные | Где находятся | Сохраняются после перезапуска |
|---|---|---|
| Личные данные после кнопки «Сохранить» | SQLite | Да, пока сохранена база этого приложения. |
| Несохранённый текст | Состояние формы | Нет. |
| Тема | `AppSettingsController` в памяти | Нет, начальное значение — тёмная. |
| Язык | `AppSettingsController` в памяти | Нет, начальное значение — русский. |

В текущем `MainScreen` при выборе другой вкладки экран аккаунта убирается из дерева. Поэтому несохранённый черновик может пропасть при уходе на другую вкладку. При возвращении форма заполняется сохранённым профилем. Обычная прокрутка страницы и переключение языка работают иначе: форма остаётся в дереве.

## 13. Действия аккаунта и аватар

В `account_section.dart` расположены:

- смена пароля;
- привязка соцсети;
- удаление аккаунта;
- выход из аккаунта.

Сейчас это визуальные заглушки. Нажатия не выполняют операций с учётной записью.

Аватар в `profile_header.dart` тоже заглушка. Камера, галерея и загрузка в Firebase пока не подключены.

Поля email и телефон в форме — просто локальные данные профиля. Ввод email не является регистрацией, а сохранение профиля не является авторизацией.

## 15. Проверка на компьютере с Flutter

Команды выполняются из корня проекта, где лежит `pubspec.yaml`:

```bash
flutter pub get
flutter gen-l10n
flutter analyze
flutter test
flutter run
```

Для десктопа выбирай поддерживаемое подключённое устройство. В `main.dart` предусмотрена инициализация SQLite FFI для Windows, Linux и macOS. Веб-версия SQLite текущим кодом не настроена.

Если не найден `app_localizations.dart`, сначала проверь выполнение `flutter pub get` и `flutter gen-l10n`. Этот файл создаётся генератором; писать его вручную не нужно.

При переносе проекта база на другом компьютере обычно будет отдельной. Перенос только исходников не переносит автоматически заполненный профиль из базы прежнего устройства.

### Сценарий 1. Первое заполнение

1. Открой вкладку аккаунта.
2. Убедись, что пустые измерения показаны тире.
3. Введи имя, рост 182, вес 78 и цель 72.
4. До нажатия «Сохранить» проверь, что верхние карточки ещё не изменились.
5. Нажми «Сохранить».
6. Проверь имя и три значения сверху.

### Сценарий 2. Повторное сохранение

1. Измени вес на `77,5`.
2. Нажми «Сохранить».
3. Проверь, что сверху отображается `77.5`.
4. Перезапусти приложение и снова открой аккаунт.
5. Должны загрузиться сохранённые данные.

### Сценарий 3. Ошибки

Проверь по очереди, исправляя ошибку после каждого опыта:

- отрицательный вес;
- буквы вместо роста;
- дату `31.02.2000`;
- дату в будущем;
- email без `@`.

Ожидается диалог ошибки. Новые некорректные данные не должны попасть в верхние карточки и базу.

Также очисти одно измерение и сохрани: пустое поле допустимо, соответствующая карточка должна показать тире.

### Сценарий 4. Язык и тема

1. Введи новое имя, но пока не сохраняй.
2. Прокрути страницу к настройкам.
3. Выбери EN: подписи должны стать английскими.
4. Верни RU: подписи должны стать русскими.
5. Введённое имя должно остаться в поле.
6. Переключи тему и проверь читаемость полей и карточек.
7. Нажми «Сохранить», затем перезапусти приложение.
8. Профиль должен остаться, а тема и язык вернутся к начальным значениям.

В `test/widget_test.dart` добавлена автоматическая проверка переключения языка и сохранения текста в форме при таком переключении. Этот тест не проверяет запись в SQLite.

Запуск Flutter, генерация и автоматический тест в окружении подготовки изменений не выполнялись из-за отсутствия SDK. Команды и сценарии выше предназначены для проверки на компьютере, где Flutter установлен.

## 16. Частые вопросы преподавателя

**Почему экран разделён на файлы?**

Каждый блок отвечает за свою часть. Экран собирает страницу, форма работает с вводом, шапка отображает значения, контроллер управляет состоянием, DAO выполняет запросы. Так легче искать и менять нужный код.

**Почему форма не пишет в БД напрямую?**

Запросы вынесены в DAO, а порядок сохранения и обновление состояния — в контроллер. Форма отвечает за ввод и проверку данных.

**Почему изменение текста не обновляет карточку веса сразу?**

Карточка читает сохранённую модель. Введённое значение остаётся черновиком до успешной записи по кнопке.

**Кто обновляет экран после сохранения?**

Контроллер вызывает `notifyListeners()`. Экран подписан через `watch`, поэтому перестраивается и передаёт новый профиль в шапку.

**Почему не используется setState во всём приложении?**

`setState` применяется для локального состояния формы. Общие данные профиля находятся в `ChangeNotifier`, на который могут подписаться разные виджеты.

**Почему профиль не создаётся заново при каждом сохранении в таблице?**

Используется постоянный `id = 1` и `ConflictAlgorithm.replace`. Поэтому заменяется существующая запись единственного локального профиля.

**Где находится пароль пользователя?**

Пароля пока нет. Авторизация не реализована. Форма хранит личные данные, а не учётную запись.

**Почему StatelessWidget может показывать новое имя?**

Родитель передаёт ему новую модель при перестроении. Отсутствие своего состояния не запрещает обновление параметров.

## 17. Готовый короткий рассказ для защиты

> Экран аккаунта разделён на четыре виджета: шапку, форму личных данных, настройки приложения и действия аккаунта. Главный экран проверяет состояние загрузки и собирает эти блоки.
>
> При первом получении контроллера профиля вызывается загрузка. Контроллер обращается к DAO, DAO читает запись из SQLite и преобразует её в модель UserProfile. После загрузки контроллер уведомляет экран через notifyListeners.
>
> У каждого поля формы свой TextEditingController. Начальные значения задаются в initState. При редактировании меняется только текст формы, поэтому карточки сверху продолжают показывать сохранённые значения.
>
> По кнопке «Сохранить» форма читает и проверяет поля, создаёт новую модель и передаёт её контроллеру. Контроллер через DAO сохраняет модель в SQLite. После успешной записи он обновляет своё состояние и уведомляет интерфейс. Шапка получает новые значения и перестраивается.
>
> Тема и язык находятся в отдельном контроллере настроек и применяются через CupertinoApp. Они пока хранятся в памяти, а личные данные сохраняются в базе. Аватар и действия аккаунта остаются заглушками до подключения соответствующих функций.
